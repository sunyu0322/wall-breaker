# Wall-Breaker PRD v4.1: Evidence-First Prompt Upgrade

## 1. 本次修订目标

上一版 MVP 已经跑通 SiliconFlow + DeepSeek 的调用链路，但暴露出两个核心问题：

1. **事件研究不足**：系统只有关键词和 mock 素材时，仍然会生成貌似完整的观点文案，容易产生幻觉。
2. **风格没有对齐**：输出缺少参考文本中的“概念考古、历史脉络、资产逻辑、攻防推进、历史唯物主义升华”的结构张力。
3. **few-shot 太短**：高流量文案的门槛很高，不能只给几句示例，必须给模型足够长的原文参考语料，让它学习节奏、转折、反问、反方话术和论证密度。

v4.1 的核心原则是：

```text
没有证据，不写稿。
没有事件档案，不做结构分析。
没有证据锚点，不进入视觉匹配。
```

## 2. 证据闸门

系统必须先判断素材质量：

- 如果素材来自 mock source、example.invalid、空文本或无真实出处，则输出 `insufficient_evidence`。
- 如果只有情绪评论，没有原始事件材料，也不得生成正式文案。
- 如果关键事实缺少 raw item id，必须进入 research_gaps，而不是让模型补全。

正式写作前必须形成事件档案：

- 时间线：事件发生、扩散、回应、反转或沉寂。
- 当事方：品牌、平台、用户群体、被影响对象。
- 原始材料：争议文案、截图、视频、回应原文。
- 舆论材料：高赞评论、长文分析、反方话术、支持方话术。
- 可证事实与不可证推断：必须分层。

## 3. 风格一：考古式单口深稿

适用场景：事件背后有明显历史脉络、制度背景、社会心理和经济结构。

结构规则：

1. 用一个生活化问题开场，把观众拉进共同经验。
2. 拆解关键词本身的隐藏判断：这个词为什么天然带着道德审判？
3. 追问概念何时出现、何时流行、何时退潮。
4. 把道德化问题还原成资产、风险、家庭投资、制度激励和阶层焦虑。
5. 引入历史材料，不是为了堆知识，而是说明规范如何被特定时代制造。
6. 写到最后必须出现结构性反噬：过去规训普通人的规则，如何在今天以新问题形式回来。

语言规则：

- 口语化，但不是散漫。
- 反问多，转折快，逻辑链长。
- 可以冷嘲，但每个嘲讽后面都要跟事实或结构解释。
- 不使用空泛口号，不把“阶级”“压迫”“结构”当万能填充词。

## 4. 攻防逻辑吸收：来自《先生》参考稿

重要修订：最终视频文案不分为两类，也不输出 A/B 对话。成稿仍然是更接近《早恋》那期的单人叙述深稿。

《先生》参考稿的用途不是让系统照着写双人对话，而是学习其中的攻防能力：

结构规则：

1. 在单人口吻中先复原一个足够聪明的反方观点。
2. 反方观点不能是稻草人，要有真实说服力：引经据典、诉诸常识、诉诸秩序、诉诸“不要制造对立”。
3. 叙述者再逐层拆前提：词源/事实、现实使用、权力位置、议题化过程。
4. 核心追问是：为什么一个诉求会变成议题？是谁把它变成战场？
5. 最终指出：强势一方“怎么做都有理”的解释能力，本身就是结构性不公的证据。
6. 结尾升华到历史唯物主义：方案不是天然正确，而是在具体历史运动中被反对者的压制生产出来。

语言规则：

- 不能写成 A/B 对话。
- 可以写“有人会说……这套话术听起来完整，但问题恰恰在这里……”。
- 要像在审问概念，而不是宣泄情绪。
- 推进要层层加码，每一轮都改变争论层级。

## 5. 长参考语料

系统现在将参考文档提取为项目语料：

- `references/style_corpus/early-love-subtitle.md`
- `references/style_corpus/should-call-women-xiansheng.md`

提示词会自动加载这些长语料。模型必须学习其语言与结构，但不得照抄句子，也不得把参考语料中的事实挪用到当前事件。

## 6. Prompt 变更

### Reasoner

新增字段：

- `status`: `ready` 或 `insufficient_evidence`
- `event_file`
- `research_gaps`
- `evidence_map`

Reasoner 的第一任务从“结构分析”改为“证据审查 + 事件建档”。

### Writer

Writer 必须读取 `analysis.status`：

- `insufficient_evidence`: 只输出研究缺口清单。
- `ready`: 才输出正式文案。

正式文案必须在事实段落末尾标注 `[E:raw_item_id]`。

## 7. MVP 操作方式

当前真实平台抓取尚未完成，因此要避免幻觉，有两种运行方式：

### 方式 A：无素材运行

```powershell
python -m wallbreaker.cli run "事件关键词"
```

结果会生成研究缺口清单，而不是硬写文案。

### 方式 B：提供本地真实材料

创建一个文本文件，例如：

```text
sources/oppo-mothers-day.txt
```

每条材料用独立段落保存，多条材料用 `---` 分隔：

```text
材料一：原始文案、出处、链接、截图 OCR。
---
材料二：品牌回应、出处、链接。
---
材料三：高赞评论或长文分析、出处、链接。
```

运行：

```powershell
python -m wallbreaker.cli run "oppo母亲节文案塌房事件" --source-file sources/oppo-mothers-day.txt
```

这会让系统基于你提供的真实素材生成事件档案和文案。

## 8. 后续路线

1. 已接入搜索 API 适配层：Bing、Serper、DuckDuckGo HTML fallback。
2. 当前自动检索采用站点定向查询，还原事实骨架和多平台舆论切片。
3. 下一步增加 Playwright 登录态深爬、截图和 OCR 入库。
4. 增加 Web UI，让用户先确认事件档案，再进入文案生成。
5. 将视觉匹配延后到人工确认 script.md 之后。

## 9. 自动检索策略

MVP 阶段不直接承诺突破各平台反爬，而是先通过搜索 API 做多源覆盖：

- `事实骨架`: `事件关键词 + 原文 + 回应 + 争议 + 时间线`
- `新闻`: `事件关键词 + 媒体报道 + 回应 + 道歉`
- `公众号`: `site:mp.weixin.qq.com`
- `知乎`: `site:zhihu.com`
- `微博`: `site:weibo.com`
- `B站`: `site:bilibili.com`
- `小红书`: `site:xiaohongshu.com`

每条搜索结果必须原样入库：

- 搜索查询词
- 标题
- 摘要
- URL
- 可访问页面正文摘录
- 检索 provider
- 排名

搜索结果不是最终事实，只是事实研究的入口。Reasoner 仍必须区分“搜索摘要”“原始材料”“媒体报道”“舆论评论”。
